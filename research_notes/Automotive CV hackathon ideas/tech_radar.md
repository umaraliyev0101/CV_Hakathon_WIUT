# Tech radar: practical computer vision for automotive / road-safety products (state of the art as of 2026-10-10)

> Method note (not a findings section). Compiled 2026-10-10. The shared WebSearch budget (200 calls across all agents) ran out mid-session, so discovery was done with the Hugging Face Hub API, the GitHub API (`gh`), and direct fetches of primary pages (model cards, LICENSE files, vendor docs and pricing pages). Licence verdict tags used below: **OK** = commercial use allowed by the licence text read; **OK+cond** = commercial use allowed but with attribution / gating / use restrictions; **NC** = non-commercial or research-only; **COPYLEFT** = AGPL/GPL obligations; **UNCLEAR** = could not verify. "Vendor-measured" = number comes from the model owner's own benchmark. Per-image costs are in section 3, everything marked "(inference)" is my own arithmetic from cited numbers.

## 1. Newest open models and their licences (detectors, segmentation, depth/3D, features, VLMs, OCR/plates, face/gaze/rPPG, tracking, anomaly, forensics, motion magnification)

### Takeaway
For a commercial-mode startup with a public web demo, the clean permissive stack today is RF-DETR (Nano-Large, plus Seg), D-FINE / RT-DETR, SAM 2.1 / EdgeTAM (SAM 3 under Meta's SAM License), DA3 Small/Base/Metric/Mono or Depth-Anything-V2-Small or MoGe-2, Apache-2.0 VLMs (Gemma 4, Qwen3.5, Qwen3-VL, Qwen-Drive), PP-OCRv6 + fast-plate-ocr, and MediaPipe. The traps are YOLO26 (AGPL-3.0), DEIMv2 (switched to non-commercial in 2026), Depth Pro / UniDepth / MASt3R / DA3-Large-Giant / original VGGT / LocateAnything-3B (all non-commercial), and BoxMOT / Nomeroff-Net / OpenALPR (copyleft).

### Inferences
- For a startup-mode product, RF-DETR Nano-Large (Apache-2.0) is the strongest permissive detector: on vendor-measured T4 TensorRT numbers RF-DETR-Medium (54.7 AP, 4.4 ms) is roughly level with YOLO26m (53.1 mAP, 4.7 ms) while avoiding AGPL / Enterprise-licence exposure. The two benchmark setups differ, so treat this as parity, not a win.
- DEIMv2 looks attractive on accuracy-per-latency but its 2026 licence forbids exactly what the hackathon asks for (a hosted public demo plus a business case); D-FINE / RT-DETR are the Apache-2.0 fallbacks.
- Teacher-student is the cheap route to "no dataset": use SAM 3 text prompts (or Gemini / Claude boxes) to auto-label self-collected images, then train a small RF-DETR / D-FINE to ship (SAM 3's licence permits commercial use under its conditions).
- For depth in a commercial demo use only Apache/MIT weights: DA3 Small/Base/Metric-Large/Mono-Large, Depth-Anything-V2-Small, or MoGe-2; avoid Depth Pro, UniDepth, MASt3R, DA3-Large/Giant and the original VGGT checkpoint.
- Driver monitoring is feasible fully in-browser: MediaPipe Face Landmarker gives eye-blink/jaw-open blendshapes and head-pose matrix per frame, so drowsiness / yawn / head-turn rules need no custom training; gaze and rPPG models carry research-data or use-restriction licences.
- "Image to decision" has new off-the-shelf shapes in 2026: decision models (Clef / d1 / Jev) output calibrated per-option probabilities in one pass, which fits triage (e.g., severity classes) better than free-text VLM answers; vision quality is unbenchmarked in the sources read, so test before relying on it.
- AI-image fraud checks cannot be outsourced to a VLM, and the best open forensic models (TruFor, B-Free) are non-commercial; a defensible product design is provenance (C2PA / SynthID check) + capture-time controls + human review, not a "fake detector" claim.

### Gaps
- No independent accuracy benchmarks found for LocateAnything, Qwen-Drive, Clef/d1 on vision tasks, or any AI-image detector on 2026 generators.
- Licence of Metric3D weights, Moondream 3.1's custom licence, PML 1.0, Qwen3.8-Flash-Next's licence, DA3-LARGE-1.1 (README vs HF conflict) and SAM-3 derivative weights was not resolved.
- Cyrillic / Uzbek-format plate coverage of PP-OCRv6 and fast-plate-ocr global models was not verified; DEIMv2 latency hardware not captured.
- Training-data licences for gaze models (Gaze360 / MPIIGaze) not verified. Qwen2.5-VL/Gemma 3n/InternVL details are from HF tags only.

## 2. In-browser and on-device inference today (WebGPU, runtimes, FPS and size limits, edge boards)

### Takeaway
WebGPU is now broadly deployable (about 86% of global browser share with full support, including iOS/iPadOS 26+ and Chrome on Android 12+), and Transformers.js v4 / ONNX Runtime Web are the practical runtimes, with ready-made WebGPU demos for YOLO26, RF-DETR, SAM 3, Gemma 4, Qwen3.5 and LFM2-VL. I found no published phone-browser FPS for detectors, so quote only native or desktop numbers as such and keep a server fallback.

### Cited Findings

#### 2a. WebGPU availability
- Per caniuse data (file fetched 2026-10-10): global usage with full WebGPU support 85.72%, partial 3.05%. Chrome/Edge supported from 113, Opera 99, Samsung Internet 24, Chrome for Android listed as supported (v154), iOS Safari full support from 26.0 through 27.2; desktop Safari 26+ is "partial" meaning enabled by default only on macOS 26 Tahoe or later; Firefox "partial" from 141 (Windows only; 145+ adds macOS 26 on Apple Silicon); Firefox for Android: not supported. — [caniuse WebGPU](https://caniuse.com/webgpu); [data file](https://github.com/Fyrd/caniuse/blob/main/features-json/webgpu.json)

### Inferences
- Practical phone-browser plan: nano-class detector (YOLO26n at about 9.5 MB only if AGPL is acceptable; otherwise D-FINE-N at 15 MB or RF-DETR-Nano at about 30.5M params, roughly 120 MB in fp32 by 4 bytes/param) via Transformers.js/ORT-Web WebGPU, with WASM or server fallback for Firefox-Android and pre-iOS-26 devices (about 11-14% of global share lacks full WebGPU).
- Only sub-1B VLMs (Qwen3.5-0.8B, LFM2.5-VL-450M, SmolVLM2-256M/500M) are realistic in a phone tab; Gemma 4 E2B/E4B and everything bigger belongs on a server or API, or on a laptop with WebGPU.
- Quote speeds with the hardware they were measured on: e.g., "YOLO26n 4.6 ms on Jetson Orin Nano Super (TensorRT FP16)" or "RF-DETR-Medium 4.4 ms on T4", and treat phone-browser FPS as something the team must measure itself on 2-3 phones before the demo.
- A tradeoff for the business case: edge node about USD 505 (Pi 5 16 GB + AI HAT+ 2, excluding camera/PSU) versus zero marginal compute for a browser demo where the judge's device does the work (inference from the cited prices).

### Gaps
- No verified FPS / latency for any detector, depth or segmentation model running in a mobile browser (the only searches that might have found them hit the search budget).

- Cloud Run / Android-GPU compatibility lists (which Mali/Adreno parts pass Chrome's WebGPU blocklist) not found.

- **Image-generation API prices (for synthetic data)**: Nano Banana 2.1 USD 0.0336 (1K) / 0.0504 (2K) / 0.113 (4K); Gemini 3.1 Flash-Lite Image 0.0336 (1K); Gemini 3.1 Flash Image 0.067 (1K); Nano Banana Pro 0.134 (1K/2K), 0.24 (4K); Gemini 2.5 Flash Image 0.039 but scheduled to shut down on 2026-10-02 (already past). — [Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing)

### Inferences
- Cost per photo (1000x1000 px, 300-token prompt, 300-token JSON answer; my arithmetic): Claude Haiku 5.5 = 1,596 in x $0.10/M + 300 out x $0.50/M = about $0.00031 (batch about $0.00016); Gemini 2.5 Flash-Lite = (4 tiles x 258 + 300) x $0.10/M + 300 x $0.40/M = about $0.00025; Gemini 3.5 Flash-Lite = 1,332 x $0.30/M + 300 x $2.50/M = about $0.00115 (3.x "thinking" tokens bill as output, keep thinking minimal); gpt-6-luna has Haiku 5.5's list price but its image-token count is undocumented. A 12-photo inspection therefore costs about $0.004 (Haiku 5.5) to about $0.014 (Gemini 3.5 Flash-Lite).
- Self-hosted detector on Modal (assuming 50 ms per request including overhead): T4 $0.000164/s x 0.05 s = about $0.0000082 per image; L4 about $0.0000111; the $30/month credit covers roughly 2.7-3.7 million such requests. But with sparse demo traffic the default 60 s idle window bills about $0.0098 (T4) / $0.0133 (L4) per isolated cold hit, so set a short scaledown or keep a warm CPU/edge path.
- Roboflow-hosted RF-DETR Nano is 8,000 images/credit, so the free 10 credits cover about 80,000 images/month with a commercial licence included, a zero-ops option for the demo backend.
- Cheapest defensible architecture for the business case: on-device/browser detector for the high-volume step, then one VLM call per inspection only for the ambiguous crops (cost is then dominated by the VLM, around a few tenths of a cent).
- Workers AI Clef-flash at $0.038 per million input tokens would cost under $0.0001 per photo if a photo is about 1,300 tokens (assumed), but vision quality is unbenchmarked in the sources read.

### Gaps
- Cloud Run GPU per-second rates, OpenAI image-token accounting, Gemini 3.x per-image token counts at default `media_resolution`, and OpenRouter free-model rate limits were not captured.
- Latency (ms per photo) of the hosted VLM APIs was not measured; no source for Qwen/Gemma API image-token formulas.
- RunPod flex-vs-active split and Vast.ai / TensorDock spot prices not collected.

## 4. Public datasets relevant to automotive and road CV (sizes, licences)

### Takeaway
Licensable (CC BY / CC BY-SA / MIT) data exists for road damage (RDD2022), vehicle damage (AutoDamageIQ, a merged set), helmets, synthetic driver monitoring, and AV driving (ZOD, Cosmos-Drive-Dreams), but most famous benchmarks are non-commercial or form-gated (CarDD, DMD, MVTec AD, LISA lights, AI City). I found no verifiable dataset for Uzbek plates, dashboard warning lights, smoky vehicles, tyre sidewalls or street-level floods, so those need to be collected or synthesized and declared.

### Cited Findings

#### 4a. Vehicle damage and parts
- **CarDD** (IEEE T-ITS 2023, vol. 24 no. 7 pp. 7202-7214): 4,000 high-resolution images, more than 9,000 instances, six damage categories, for detection and segmentation; download only after filling a licensing form (terms for commercial use not stated) — **UNCLEAR/gated**. — [CarDD](https://cardd-ustc.github.io/)
- **AutoDamageIQ** (HF, 2026-08-05): YOLO-format detection set with 13,089 train + 2,094 val images, about 42,419 boxes, 6 classes, CC-BY-4.0; the card describes a unified set and lists upstream sources (list truncated in my fetch), so check provenance and upstream licences. — [HF](https://huggingface.co/datasets/tugberkkalay/autodamageiq-vehicle-damage-dataset)
- **Car Parts and Damages Polygon Dataset** (HF; MIT tag): 1,812 high-resolution images with polygon masks for either parts or damages. — [HF](https://huggingface.co/datasets/DrBimmer/car-parts-and-damage-dataset)
- **VehiDE**: only an HF mirror without a card (`hoangnguyenvan/VehiDE-dataset`) and a Kaggle title page could be reached; size and licence not verified. — [HF mirror](https://huggingface.co/datasets/hoangnguyenvan/VehiDE-dataset)
- **Roboflow 100 / RF100-VL**: 100 detection datasets across 7 domains, e.g., `vehicles-q0x2v` mirrored with CC-BY-4.0 (1K-10K images); benchmark code Apache-2.0. — [vehicles-q0x2v](https://huggingface.co/datasets/LibreYOLO/vehicles-q0x2v); [rf100-vl](https://github.com/roboflow/rf100-vl)

#### 4b. Plates (incl. CIS)
- **CCPD** (ECCV 2018, Chinese plates; repo MIT; dataset size and data terms not captured). — [CCPD](https://github.com/detectRecog/CCPD)
- **AUTO.RIA Numberplate Dataset** (supplied by RIA.com; zip dated 2021-07-21; country coverage not stated) and AUTO.RIA Options Dataset (trains a country/plate-type classifier reported as 99% accurate); size and data licence not stated in the README; the Nomeroff-Net code is GPL-3.0. — [Nomeroff-Net](https://github.com/ria-com/nomeroff-net)
- HF `mabo7237/license-plates-700k` (MIT tag, no card, provenance unknown) — **UNCLEAR**. — [HF](https://huggingface.co/datasets/mabo7237/license-plates-700k)
- No Uzbek (or Kazakh) plate dataset surfaced in HF dataset searches; `Dognellaf/russian-road-signs` (CC-BY-4.0, 10K-100K frames, manually labelled signs from video) is the closest CIS-flavoured traffic set found. — [HF](https://huggingface.co/datasets/Dognellaf/russian-road-signs)

#### 4c. Adverse weather, night, general driving
- **ACDC** (ICCV 2021): 8,012 images, half (4,006) equally split across fog, night, rain, snow, each with pixel-level panoptic annotation, a matching normal-condition image and a validity mask; licence not verified (site is JavaScript-only). — [arXiv 2104.13395](https://arxiv.org/abs/2104.13395); [site](https://acdc.vision.ee.ethz.ch/)
- **Zenseact Open Dataset (ZOD)**: about 100k frames, 1,473 sequences, 29 drives from 14 European countries, 120-degree 8 MP camera + 3 LiDAR + radar; CC BY-SA 4.0 and the page states commercial use is permitted (**OK+cond**: share-alike). — [ZOD](https://zod.zenseact.com/)
- **IDD** (India Driving Dataset): 10,000 finely annotated images, 34 classes, 182 drive sequences; the licence "will be displayed before downloading" — **UNCLEAR**. — [IDD](https://idd.insaan.iiit.ac.in/)
- **BDD100K**: toolkit is BSD-3-Clause; the dataset's own terms and size could not be verified (official data site had a certificate error, docs host did not resolve). — [toolkit](https://github.com/bdd100k/bdd100k)
- **NVIDIA PhysicalAI-Autonomous-Vehicles** (HF, licence "other", 237K downloads, no card) [HF](https://huggingface.co/datasets/nvidia/PhysicalAI-Autonomous-Vehicles); **Cosmos-Drive-Dreams** synthetic AV videos (CC-BY-4.0, more than 1 TB) [HF](https://huggingface.co/datasets/nvidia/PhysicalAI-Autonomous-Vehicle-Cosmos-Drive-Dreams).
- Dark Zurich (night/twilight segmentation, Sakaridis et al., arXiv 1901.05946): counts and licence not captured (ETH host did not resolve). — [paper](https://arxiv.org/abs/1901.05946)

#### 4d. Road damage
- **RDD2022**: 47,420 road images from six countries (Japan, India, Czech Republic, Norway, US, China), more than 55,000 annotated damages in four classes (longitudinal crack, transverse crack, alligator crack, pothole); CC BY 4.0 (**OK**); 13.3 GB zip on figshare; HF has community YOLO12 models trained on it. — [figshare](https://figshare.com/articles/dataset/RDD2022_-_The_multi-national_Road_Damage_Dataset_released_through_CRDDC_2022/21431547); [GitHub](https://github.com/sekilab/RoadDamageDetector)

#### 4e. Driver monitoring, distraction, helmets, collisions
- **DMD (Vicomtech)**: about 25 TB raw, three cameras (body, face, hands), RGB (public part) with IR/depth removed, 27% women / 73% men, annotations for distraction, hands on wheel, gaze zones, fatigue (yawning, microsleep); **CC BY-NC-ND 4.0, academic use only** (**NC**), adults only. — [DMD](https://dmd.vicomtech.org/)
- **YawDD**: 351 videos (322 from set one, 29 from set two), dash or under-mirror camera; no licence named, "all videos can be used for research", free IEEE DataPort login. — [IEEE DataPort](https://ieee-dataport.org/open-access/yawdd-yawning-detection-dataset)
- **Synthetic DMS** by AnywayLabs (HF, CC-BY-4.0, 1K-10K samples, 2026-05) and a second `synthetic-driver-monitoring-detection` upload (CC-BY-4.0). — [AnywayLabs](https://huggingface.co/datasets/anywaylabs/synthetic-driver-monitoring-detection)
- **AI City Challenge 2023 Track 5** (motorcycle helmet rule violations): 100 training videos of 20 s at 10 fps, 1920x1080, 7 classes (motorbike, driver/passenger-1/passenger-2 with or without helmet); separate data licence agreement and request form; teams that want leaderboard standing may not use external data. — [AI City 2023](https://www.aicitychallenge.org/2023-data-and-evaluation/)
- **Helmets on HF**: `bike-helmet-dataset` 1,376 images (1,185 train / 127 val / 64 test, COCO format, CC-BY-4.0) [HF](https://huggingface.co/datasets/cute-face/bike-helmet-dataset); `IITU_Safety-Helmet_Dataset_v1.0` (CC-BY-4.0, 1K-10K, no card) [HF](https://huggingface.co/datasets/ersace/IITU_Safety-Helmet_Dataset_v1.0).
- **Nexar collision prediction** (dashcam crash/near-miss; HF licence tag "other", 1K-10K videos, no card) — **UNCLEAR**. — [HF](https://huggingface.co/datasets/nexar-ai/nexar_collision_prediction)

#### 4f. Signs, lights, tyres, floods, defects
- **LISA Traffic Lights** (HF YOLO export, 10K-100K images, 7 classes) is **CC BY-NC-SA 4.0 (NC)**. — [HF](https://huggingface.co/datasets/dronefreak/LISA-Traffic-Lights)
- **Tyres**: only `NMiriams/Good_Tires` (CC-BY-4.0, under 1K images) surfaced. — [HF](https://huggingface.co/datasets/NMiriams/Good_Tires)
- **Floods**: `ai-for-good-lab/ai4g-flood-dataset` (MIT) is global Sentinel-1 SAR flood detection (Nature Communications 2025), not street-level imagery. — [HF](https://huggingface.co/datasets/ai-for-good-lab/ai4g-flood-dataset)
- **MVTec AD** (industrial surface defects): CC BY-NC-SA 4.0, "not allowed to use the dataset for commercial purposes". — [MVTec](https://www.mvtec.com/company/research/datasets/mvtec-ad)

### Inferences
- A fully licensable starter bundle for a damage-triage product: AutoDamageIQ (CC BY, after provenance check) + the polygon parts/damages set + self-collected phone photos, with SAM 3 or a VLM used to auto-label, then synthetic augmentation (section 5) for night/rain.
- For driver monitoring, DMD and similar academic sets cannot be used in a commercial product, so either train nothing (MediaPipe landmarks + rules) or use CC BY synthetic data plus self-recorded consenting volunteers.
- Night/rain evidence for the engineering constraint can come from ACDC (research evaluation only, licence unverified) plus a small self-collected local test set; ZOD is the one big driving set with an explicit commercial-use statement.
- Local plates (Uzbek formats) will almost certainly need an own dataset: collect plates (with consent / blur policy), render synthetic plates with the right fonts and layouts, and fine-tune fast-plate-ocr.

### Gaps
- Not verified: sizes and licences of GTSRB, Mapillary Traffic Sign Dataset, State Farm and AUC distracted-driver sets (hosts unreachable), Stanford Cars / VMMRdb, CompCars, Dark Zurich, KITTI/Cityscapes-type sets, BDD100K and ACDC licence text, IDD terms, VehiDE, CCPD size, NTHU-DDD, Roboflow Universe totals.
- No verifiable datasets found for dashboard warning lights, smoky/exhaust vehicles, tyre sidewall/DOT codes, street-level flood images, Uzbek/Kazakh plates.

## 5. Synthetic-data tools

### Takeaway
The commercially clean generative stack is FLUX.2 [klein] 4B, Qwen-Image-Edit-2511 and Z-Image-Turbo (all Apache-2.0) for inpainting/edits, NVIDIA Cosmos 3 (OpenMDW 1.1) and Cosmos-Transfer2.5 (NVIDIA Open Model License) for video weather/lighting transfer, and CARLA (MIT) whose 0.9.16 release integrates Cosmos Transfer and NuRec. Several popular tools are non-commercial (FLUX dev / Kontext / klein-9B, SDXL-Turbo) or AGPL (AlbumentationsX).

### Cited Findings

#### 5a. Diffusion editing / inpainting / img2img
- **FLUX.2 [klein] 4B** (2026-01-14): 3.9B params, Apache-2.0 **OK**; klein 9B and FLUX.2 [dev] (32B) are non-commercial (**NC**); FLUX.1 Kontext [dev] (editing) is non-commercial; FLUX.1 [schnell] is Apache-2.0. — [klein-4B](https://huggingface.co/black-forest-labs/FLUX.2-klein-4B); [klein-9B](https://huggingface.co/black-forest-labs/FLUX.2-klein-9B); [FLUX.2-dev](https://huggingface.co/black-forest-labs/FLUX.2-dev); [Kontext-dev](https://huggingface.co/black-forest-labs/FLUX.1-Kontext-dev); [schnell](https://huggingface.co/black-forest-labs/FLUX.1-schnell)
- **Qwen-Image-Edit-2511** (2025-12-17; 20.4B params; Apache-2.0 **OK**); **Z-Image-Turbo** (Tongyi, 2025-11-25; 6.2B; Apache-2.0 **OK**); **Qwen-Image-2.1** (2026-09-14) uses the "qwen-research" licence (**UNCLEAR/NC-leaning**). — [Qwen-Image-Edit-2511](https://huggingface.co/Qwen/Qwen-Image-Edit-2511); [Z-Image-Turbo](https://huggingface.co/Tongyi-MAI/Z-Image-Turbo); [Qwen-Image-2.1](https://huggingface.co/Qwen/Qwen-Image-2.1)
- **Classic inpainting / control**: SDXL inpainting 0.1 and ControlNet canny SDXL are OpenRAIL++ (use-restriction licence, commercial allowed) [inpaint](https://huggingface.co/diffusers/stable-diffusion-xl-1.0-inpainting-0.1); [ControlNet](https://huggingface.co/diffusers/controlnet-canny-sdxl-1.0); Stable Diffusion 3.5 Medium uses the Stability AI Community License [HF](https://huggingface.co/stabilityai/stable-diffusion-3.5-medium).
- **img2img-turbo** (MIT code, SD-Turbo based): one-step unpaired models `day_to_night`, `night_to_day`, `clear_to_rainy`, `rainy_to_clear`; base-model weights licence unclear (SDXL-Turbo is `sai-nc-community`, non-commercial). — [repo](https://github.com/GaParmar/img2img-turbo); [SDXL-Turbo](https://huggingface.co/stabilityai/sdxl-turbo)
- **API editors**: Nano Banana family via Gemini API (prices in section 3). — [Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing)

#### 5b. NVIDIA Cosmos and CARLA
- **Cosmos 3** ("omnimodal world models for Physical AI", OpenMDW 1.1, "ready for commercial and non-commercial use"): Cosmos3-Edge 4B (HF 3.9B params; released 2026-07-20; 688K downloads), Cosmos3-Nano 16B (2026-03), Cosmos3-Super 65B image-to-video; per the Nano card the family includes a reasoner (structured reasoning, 2D/3D point localization, bounding boxes) and accepts action inputs including autonomous-vehicle (9D) trajectories. — [Cosmos3-Edge](https://huggingface.co/nvidia/Cosmos3-Edge); [Cosmos3-Nano](https://huggingface.co/nvidia/Cosmos3-Nano); [OpenMDW 1.1](https://openmdw.ai/license/1-1/)
- **Cosmos-Transfer2.5-2B** (2025-10-06): multi-control video-to-video (blurred RGB, Canny edge, segmentation, depth), 2.36B params, minimum 65.4 GB VRAM, outputs 16 FPS mp4 matching input length, examples include sim-to-real and turning dashcam footage into a snowstorm, AV multiview checkpoint (`/auto`); model weights under NVIDIA Open Model License ("Models are commercially usable"), code Apache-2.0; repo marked no longer under active development with users pointed to Cosmos 3. — [GitHub](https://github.com/nvidia-cosmos/cosmos-transfer2.5); [HF card](https://huggingface.co/nvidia/Cosmos-Transfer2.5-2B)
- **CARLA** (MIT; 0.10.0 on Unreal Engine 5 released 2024-12-19; 0.9.16 released 2025-09-16 adds NVIDIA Cosmos Transfer1 and NuRec integration, SimReady OpenUSD / MDL converters, left-hand-traffic maps, vehicle doors in recorder). — [releases](https://github.com/carla-simulator/carla/releases); [repo](https://github.com/carla-simulator/carla)
- **NVIDIA Isaac Sim** (open-sourced, Apache-2.0 badge in README; RTX multi-sensor rendering; GPU required). — [repo](https://github.com/isaac-sim/IsaacSim)

#### 5c. Procedural / 3D and augmentation libraries
- **BlenderProc** (procedural Blender pipeline for photoreal training images) is **GPL-3.0 COPYLEFT** [repo](https://github.com/DLR-RM/BlenderProc); **Kubric** (Google; semi-realistic multi-object synthetic videos) is Apache-2.0 [repo](https://github.com/google-research/kubric).
- **Albumentations** (MIT) was archived (last push 2025-06-25); its successor **AlbumentationsX** is "AGPL-3.0-only or commercial licensing" (**COPYLEFT**). `imagecorruptions` (Apache-2.0; "Python package to corrupt arbitrary images", pushed 2025-05-06) is a permissive alternative for weather-style corruptions (check which corruptions it ships before relying on it). — [Albumentations](https://github.com/albumentations-team/albumentations); [AlbumentationsX](https://github.com/albumentations-team/AlbumentationsX); [imagecorruptions](https://github.com/bethgelab/imagecorruptions)
- **Synthetic licence-plate generators**: only small or unmaintained repos found (e.g., a Bangla plate generator, MIT, last push 2020-12; others without licence); no maintained open generator for Uzbek/CIS layouts surfaced. — [bangla-license-plate-generator](https://github.com/zabir-nabil/bangla-license-plate-generator)

### Inferences
- Night/rain/dust augmentation recipe with clean licences: (a) photo-level edits with FLUX.2 [klein] 4B or Qwen-Image-Edit-2511 on a rented 24-48 GB GPU (section 3 prices), keeping the original boxes/masks; (b) video-level weather/lighting with Cosmos Transfer (needs about 65 GB VRAM, so a rented A100/H100 or Cloud Run RTX PRO 6000); (c) cheap rule-based weather-style corruptions via `imagecorruptions` (check which ones it ships) rather than AlbumentationsX unless AGPL is acceptable.
- Damage synthesis: inpaint scratches/dents with an Apache-2.0 editor inside masks, so the mask doubles as a free label; declare generation method and model in the submission because the rules require source and method to be declared.
- Plates: render synthetic plates with correct fonts/layouts (own script), composite with perspective/blur/noise, validate on a small real local set; this covers "local plates" quality honestly.
- CARLA + Cosmos Transfer is the only sourced pipeline that goes from controllable simulation to photoreal weather variants, but it is heavy; for a student team the image-editing route is far cheaper.

### Gaps
- No verified GPU memory / latency numbers for FLUX.2 [klein] 4B, Qwen-Image-Edit-2511 or Z-Image-Turbo; Cosmos3-Edge VRAM requirement not captured.
- Licence of SD-Turbo / img2img-turbo day-night weights not resolved; Qwen-Image-2.1 "qwen-research" terms not read.
- No source found on measured sim-to-real gains from any of these tools for road-damage or plate tasks; no maintained open synthetic plate generator for CIS formats.
